## PURPOSE

Register all generated artifacts present in the repository — files produced by tools, compilers, or processes rather than authored by humans. For each type: document whether it is git-tracked, whether it should be git-tracked, and any action required.

---

## DEFINITIONS

**Generated artifact:** A file that is automatically produced by a tool and can be reproduced by running that tool. Generated artifacts should generally not be committed to source control unless they serve a specific purpose (e.g., lockfiles).

**Should be committed:**
- Lockfiles (`package-lock.json`) — ensures reproducible builds
- Migration files — records schema evolution

**Should NOT be committed:**
- Compiled bytecode (`.pyc`, `.class`)
- Test runner caches (`.pytest_cache/`)
- Node modules (`node_modules/`)
- Build outputs (`dist/`, `.next/`)
- Environment files with secrets

**Recommendation:** Add a comment in each `.json` report header (or a README in docs/qc/) noting that these files are generated outputs from `docs/qc/*.py` scripts and should be re-committed after re-validation.
