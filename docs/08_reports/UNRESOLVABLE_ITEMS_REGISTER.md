### OR-001: JWT_PRIVATE_KEY — Production RSA Key Pair

| Field | Value |
|---|---|
| **ID** | OR-001 |
| **Category** | CREDENTIAL |
| **Issue** | auth-service generates an ephemeral in-process RSA key when `JWT_PRIVATE_KEY` env var is absent. Every restart generates a new key, invalidating all previously issued RS256 access tokens. |
| **Why unresolvable** | An RSA private key cannot be generated by AI or derived from repository. Must be created and owned by the human operator. Must never appear in source control. |
| **Blocks production?** | Yes — ephemeral key means all tokens invalidate on restart |
| **Blocks frontend development?** | No — development uses ephemeral key without issue |
| **Required action** | Generate stable RSA key pair (minimum RSA-2048, recommended RSA-4096) |
| **How to generate** | `openssl genrsa -out private.pem 4096` then `openssl rsa -in private.pem -pubout -out public.pem` |
| **How to deploy** | Set `JWT_PRIVATE_KEY` in auth-service; set `JWT_PUBLIC_KEY` in all 32 consuming services. Use secrets manager (Vault/Doppler/AWS Secrets Manager) for production. |
