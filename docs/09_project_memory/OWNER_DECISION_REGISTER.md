## PM-OD-001: JWT_PRIVATE_KEY — RSA Key Pair

| Field | Value |
|---|---|
| **Item ID** | PM-OD-001 |
| **Original ID** | OR-001 / ITEM-17 / RISK-005 |
| **Title** | Production RSA key pair for JWT RS256 signing |
| **Classification** | OWNER-DECISION |
| **Current Status** | OPEN — awaiting operator action |
| **Original Source** | BACKEND_RISK_REGISTER.md RISK-005; OWNER-REQUIRED Compression ITEM-17 |
| **Evidence Source** | backend/services/auth-service/app/service.py — generates ephemeral in-process RSA key when JWT_PRIVATE_KEY env var is absent |
| **Resolution Source** | Not resolvable autonomously — requires human credential generation |
| **Resolution Date** | PENDING |
| **Resolved By** | Human operator |
| **Decision Summary** | Generate stable RSA-4096 key pair. Set JWT_PRIVATE_KEY in auth-service. Set JWT_PUBLIC_KEY in all 32 consuming services. Use secrets manager for production. |
| **Detailed Explanation** | auth-service generates an ephemeral RSA key pair on startup if JWT_PRIVATE_KEY is not set in the environment. Every restart of auth-service generates a new key, invalidating ALL previously issued RS256 access tokens. Users are force-logged-out on service restart. This is acceptable for development (ephemeral key is fine) but is a CRITICAL production blocker. The fix cannot be automated — an RSA private key must be generated by the operator and stored securely (never in source control). Consuming services (32 services with security.py RS256 validation) need JWT_PUBLIC_KEY set to the corresponding public key. |
| **Affected Components** | auth-service (key generation); all 32 services with RS256 JWT validation (security.py) |
| **Affected Routes** | All authenticated routes (all routes requiring JWT) |
| **Affected APIs** | All APIs (JWT is required for all non-public endpoints) |
| **Affected Workflows** | All workflows (all workflows require authentication) |
| **Affected Roles** | All roles (all authenticated users) |
| **Owner Required** | YES — credential generation and secrets management |
| **External Dependency** | NO (key generation is local; secrets manager is infrastructure choice) |
| **Future Impact** | CRITICAL — production auth fails without stable key; all users forced to re-login on restart |
| **Reopen Criteria** | N/A — resolved when key is generated and deployed |
| **Resolution Steps** | 1. `openssl genrsa -out private.pem 4096` 2. `openssl rsa -in private.pem -pubout -out public.pem` 3. Set JWT_PRIVATE_KEY=<contents of private.pem> in auth-service environment (DO NOT commit to git) 4. Set JWT_PUBLIC_KEY=<contents of public.pem> in all 32 consuming service environments 5. Use Vault / Doppler / AWS Secrets Manager / GitHub Actions Secrets for production secret storage |
| **Related Documents** | docs/08_reports/BACKEND_RISK_REGISTER.md RISK-005; docs/00_authority/AUTH_AND_TENANCY_CONTRACT.md |
| **Related Register Entries** | PM-SD-002 (cloud deployment — where secrets manager is deployed) |
